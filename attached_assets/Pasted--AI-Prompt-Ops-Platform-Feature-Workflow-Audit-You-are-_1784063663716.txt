# AI Prompt: Ops Platform Feature & Workflow Audit

You are a Principal DevOps/SRE/Platform Engineer reviewing an operations intelligence application.

Your task is to perform a comprehensive feature, workflow, architecture, and UX audit of this Ops application against **2026 industry standards, best practices, and real-world operational workflows used by modern engineering teams**.

The application is:

* Built in **Golang**
* Cross-platform: **Windows / Linux / macOS**
* Designed as a lightweight, portable, ultra-fast operations dashboard
* Modules:

  * Dashboard
  * SysOps
  * NetOps
  * DevOps
  * SecOps
  * AIOps
  * Network Design / Topology
  * Logs
  * Settings

The goal is not to create a collection of commands, but a professional **Operations Intelligence Platform** that helps engineers understand, diagnose, automate, and safely operate systems.

---

# Review Objectives

Evaluate whether the application contains the necessary:

* Features
* Workflows
* Commands
* Diagnostics
* Automation capabilities
* Visualizations
* Safety mechanisms
* Integrations
* Explanations
* User guidance

required for a modern Ops team.

Compare against workflows used by:

* System Administrators
* Network Engineers
* DevOps Engineers
* SRE Teams
* Security Operations Teams
* Platform Engineers
* Cloud Engineers

---

# Audit Methodology

Work in iterative phases.

## Phase 1 — Understand the Existing System

First:

1. Analyze the current architecture.
2. Identify:

   * Backend structure
   * Frontend structure
   * Modules
   * Services
   * APIs
   * Data flow
   * External integrations
   * Command execution model
   * Storage model
   * Logging model
3. Map existing capabilities to Ops workflows.

Do not make assumptions. Verify from the codebase.

---

Evaluate:

* Are workflows end-to-end functional?

# Phase 3 — Workflow Audit

For every feature, verify:

## Discovery

Can the application discover:

* Systems
* Networks
* Services
* Applications
* Dependencies
* Risks
* Performance issues?

---

## Diagnosis

Can users answer:

* What happened?
* Why did it happen?
* What changed?
* What is affected?
* How do I fix it?

---

## Execution

Before executing any action:

The application MUST present:

```
Action:
Restart nginx service

Reason:
Service health check detected repeated failures.

Impact:
Temporary interruption expected.

Commands:
systemctl restart nginx

Affected system:
server01.company.local

Risk:
Medium

Rollback:
Start service again.

Continue?
[Confirm] [Cancel]
```

Never silently execute destructive actions.

---

## Documentation

Every workflow should explain:

* What it does
* Why it exists
* When to use it
* Expected output
* Possible risks
* Troubleshooting steps

The application should teach users while operating.
