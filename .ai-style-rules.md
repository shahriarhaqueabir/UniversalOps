## [Naming & State-Control Rules]

- **Screen Routing**: Always use the `Screen` enum and `ScreenNames` map in `internal/common/types.go`.
- **Update Loop**: `Update` methods should delegate keyboard events to a private `handleKeyPress` helper.
- **Messages**: Use specific `ResultMsg` structs for async operation completions (e.g., `StatsResult`, `PingResultMsg`).
- **Formatting**: Use the `common` formatters (`FormatBytes`, `FormatPercent`, `FormatUptime`) for consistency.
- **Sparklines**: Use `common.RenderSparkline` for all trend visualizations.
- **Logging**: Use `common.LogInfo`, `common.LogWarn`, and `common.LogError` for session events.

## [DONTs]

- **DONT** hardcode colors in `View` methods; use `common` styles or `CurrentPalette()`.
- **DONT** put long-running operations directly in `Update`; wrap them in `tea.Cmd`.
- **DONT** use `fmt.Printf` for logging; use the `common` logger.
- **DONT** hardcode terminal UI layout dimensions; respect the `width` and `height` passed to `View`.
- **DONT** use `sed -i` or external tools to modify files; stick to the provided file editing tools.
